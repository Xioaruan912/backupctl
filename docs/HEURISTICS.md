# 启发式

启发式引擎会寻找体积大、可重新下载的目录（媒体缓存、下载目录、运行时缓存），
并且只在**既安全又有用**的前提下才自动排除。

仅凭目录名字，**永远**不会触发自动排除。

## 扫描

- 范围：每个项目源目录下 `heuristic_scan_depth` 层以内的目录（默认 2 层）。
- 大小使用 `du -x`（不跨文件系统遍历）。
- 先评估便宜的信号（名称、大小、在项目中的占比）。只有可疑候选才会进一步抽样。

## 评分（0–100）

| 信号 | 分值 |
|------|------|
| 大小 > 500 MB / 1 GB / 3 GB / 5 GB / 10 GB | +5 / +10 / +15 / +20 / +25（只取最高档） |
| 项目占比 > 40% / 60% / 75% / 90% | +5 / +10 / +20 / +25 |
| 强特征名称（`download(s)`、`dl`、`cache`、`tmp`、`temp`、`runtime`、`output(s)`、`session(s)`） | +15 |
| 弱特征名称（`media`、`video(s)`、`files`、`storage`） | +5 |
| 媒体文件比例 > 70% / > 90% | +10 / +25 |
| 平均文件 > 100 MB | +10 |
| 存在 > 1 GB 的文件 | +5 |
| 压缩文件比例 > 80% | +15 |
| 临时文件比例 > 50% | +10 |
| 源码比例 > 30% | −20 |
| 配置文件比例 > 30% | −15 |

最终分数限制在 `0..100`，并映射为：

| 分数 | 等级 |
|------|------|
| 0–49 | 正常 |
| 50–69 | 可疑（仅记录） |
| 70–84 | 建议（人工模式） |
| 85–100 | 高置信度 |

## 硬保护

在候选目录被排除之前，会扫描其中是否包含：

- 数据库：`*.db *.sqlite *.sqlite3 *.sql *.dump *.bson`
- 密钥/证书：`*.key *.pem *.p12 *.pfx`
- 敏感配置：`.env`、`.env.*`
- 用户 `protect=` 路径

只要命中一处，该候选即标记为受保护。受保护的候选**永远**不会被自动排除，
无论分数多高。

## 自动排除的五个条件

`heuristic_mode=smart` 只有在**全部**满足时才排除某个候选：

1. `score >= heuristic_auto_exclude_score`
2. 没有硬保护
3. 远端确实存在容量压力
4. 排除它确实能缓解该压力
5. 用户没有对它 `protect`

如果远端空间非常充足，即使 `score=96` 的目录仍会被备份，只记录一条日志：

```
检测到可能的下载/缓存目录 ... 但当前远端容量充足, 本次仍备份。
```

## 历史与稳定性

观测结果保存在 `state/heuristics.conf`（首次/最近发现时间、大小、分数、次数、
状态）。分数 `>= 90` 且已被自动排除至少 3 次的候选会变成
`STABLE_AUTO_EXCLUDE`。

启发式**绝不**写入 `backup.conf`。只有用户的明确操作（交互式项目向导）才能把
建议变成永久的 `exclude=` 条目。

## 预览

```bash
backupctl run --dry-run
```

dry-run 会完整执行扫描、评分、保护检查、容量检查和保留策略预览，但不执行
钩子、tar、上传或删除。
